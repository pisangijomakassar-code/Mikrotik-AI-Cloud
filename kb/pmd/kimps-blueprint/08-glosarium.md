# 08 — Glosarium

Definisi baku. Bila sebuah istilah dipakai berbeda di dokumen lain, definisi di sini yang
berlaku untuk konteks KIMPS.

| Istilah | Definisi |
|---------|----------|
| **Artefak** | Dokumen atau keluaran formal yang dihasilkan proyek dan diarsipkan sebagai bukti kerja. |
| **Baseline** | Versi lingkup, jadwal, dan biaya yang disetujui di Gate G2 dan dijadikan tolok ukur pengendalian. Hanya berubah melalui *Change Request* yang disetujui. |
| **Business Case** | Alasan bisnis menjalankan proyek: masalah, opsi, biaya, manfaat, dan risiko tidak bertindak. |
| **Change Request (CR)** | Permintaan resmi untuk mengubah *baseline*, disertai analisis dampak lima dimensi. |
| **Cost Performance Index (CPI)** | Rasio nilai pekerjaan selesai terhadap biaya aktual. < 1 berarti biaya melampaui rencana. |
| **Deliverable** | Hasil kerja nyata yang diserahkan kepada penerima dan tunduk pada kriteria penerimaan. |
| **Delegation of Authority (DoA)** | Kebijakan batas kewenangan pengambilan keputusan menurut jenjang jabatan. |
| **Estimate at Completion (EAC)** | Proyeksi total biaya proyek sampai selesai, berdasarkan kinerja sampai saat ini. |
| **Fase (F0–F5)** | Tahapan siklus hidup proyek dalam KIMPS. |
| **Gate (G0–G4)** | Titik keputusan formal antar fase. Menghasilkan GO, GO bersyarat, atau NO-GO. |
| **Isu** | Masalah yang **sudah terjadi** dan menghambat kemajuan proyek. Bandingkan dengan *Risiko*. |
| **Jalur kritis** | Rangkaian aktivitas yang menentukan durasi total proyek; keterlambatan di jalur ini menggeser tanggal selesai. |
| **Kriteria penerimaan** | Syarat terukur yang harus dipenuhi sebuah deliverable agar dinyatakan diterima. Ditetapkan di F2. |
| **Lessons Learned** | Pembelajaran terdokumentasi dari pengalaman proyek, baik keberhasilan maupun kegagalan. |
| **Milestone** | Titik penting dalam jadwal yang menandai penyelesaian bagian pekerjaan. Berdurasi nol. |
| **PMD** | Project Management Department — pemilik metodologi, penjamin mutu proses, pengelola portofolio. |
| **Post-Implementation Review (PIR)** | Tinjauan pasca-implementasi untuk menilai capaian dan manfaat proyek. |
| **Project Charter** | Dokumen yang meresmikan keberadaan proyek: sasaran, lingkup, batasan, peran, dan wewenang PM. |
| **Project Manager (PM)** | Pihak yang bertanggung jawab atas perencanaan, eksekusi, pengendalian, dan pelaporan proyek. |
| **Project Sponsor** | Pemilik manfaat bisnis; mengamankan pendanaan dan memutuskan di gate. |
| **Project Steering Committee (PSC)** | Forum pengarah lintas fungsi untuk keputusan yang melampaui kewenangan Sponsor. |
| **RACI** | Matriks peran: Responsible, Accountable, Consulted, Informed. |
| **Realisasi manfaat** | Terwujudnya manfaat bisnis yang dijanjikan dalam *business case*, diukur setelah go-live. |
| **Risiko** | Peristiwa yang **belum terjadi** dan dapat berdampak pada sasaran proyek. Bandingkan dengan *Isu*. |
| **Risk Register** | Daftar risiko beserta penilaian, strategi penanganan, pemilik, dan status. |
| **Schedule Performance Index (SPI)** | Rasio nilai pekerjaan selesai terhadap nilai pekerjaan terjadwal. < 1 berarti di belakang jadwal. |
| **Stage Gate** | Mekanisme kontrol bertahap: proyek hanya lanjut bila kriteria gate terpenuhi. |
| **Tier** | Klasifikasi bobot proyek (1 Strategis, 2 Menengah, 3 Ringan) yang menentukan beban tata kelola. |
| **UAT** | *User Acceptance Test* — pengujian oleh pengguna untuk memastikan deliverable memenuhi kebutuhan. |
| **WBS** | *Work Breakdown Structure* — penguraian lingkup proyek menjadi paket kerja yang terkelola. |
